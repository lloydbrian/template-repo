## Quick start

**Once per machine:** follow the workstation set-up in the template repo (`workstation/README.md` in `lloydbrian/python-project-template`). It installs mise, uv, Copier, Podman (and its machine on macOS) and the editor extensions. Everything else (pre-commit, ruff, mypy, pytest) comes from this project's locked dev dependencies.

**Once per clone:**

```bash
mise trust                  # allow this repo's .mise.toml to run (mise refuses untrusted config)
mise install                # installs the pinned Python 3.15, uv, gitleaks and trivy
mise run bootstrap          # creates .venv, locks if needed, installs deps and the git hooks
cp .env.example .env.dev    # fill values locally; .env.dev is git-ignored
mise run ci                 # the same checks CI runs; must pass before you push
```

**Brand-new project** (Copier just created the folder). The order matters: `git init` first, so bootstrap can install the git hooks; bootstrap before the first commit, because it creates `uv.lock`, which CI and the image build need:

```bash
git init
mise trust && mise install && mise run bootstrap
git add -A
git commit -m "chore: scaffold from python-project-template v2.0.0-rc.2"
```

Commit `uv.lock` and `.copier-answers.yml`. They are what make builds reproducible and updates possible.

## Why this layout exists

Each part of this scaffold is here to prevent a specific, recurring failure:

| Principle | The failure it prevents | How the scaffold enforces it |
|---|---|---|
| **One command is the definition of "done"** | "Passes on my machine" but fails in CI, because people run different subsets of checks | `mise run ci` (hooks, types, tests, security audit, full-history secret scan) is exactly what CI runs before any image work |
| **One Python version, declared once** | Code passes locally on 3.14 and fails in a 3.12 container, or ruff/mypy check for the wrong version | The Copier answer `python_version` feeds mise, `requires-python`, the base image and the ruff/mypy targets |
| **Reproducible installs** | A teammate or CI resolves a newer transitive dependency and something breaks | `uv.lock` is committed; CI, images and the dev container all use `uv sync --locked` |
| **Secrets never enter git or images** | Keys committed by accident or baked into a layer | `.env*` ignored (except `.env.example`), gitleaks on every commit, secrets supplied at run time |
| **Rootless, least-privilege containers** | A container break-out runs as root on the host | Podman rootless, non-root user `app` (uid 10001), read-only root filesystem, all capabilities dropped |
| **Failing gates actually fail** | `pip-audit || true`-style checks that can never go red | Every task exits non-zero on findings; coverage has a hard floor (80%) |
| **Improvements reach existing projects** | Copy-pasted scaffolds drift; fixes never propagate | Generated by Copier; `copier update` replays template changes onto this repo |

The reasoning behind each decision is recorded as ADRs in the template repo (`docs/adr/`). Record this project's own decisions in `docs/adr/` here.

## Toolchain and why each tool was chosen

| Tool | Role here | Why this one | Considered instead |
|---|---|---|---|
| **mise** | Pins Python and CLI tools per repo; runs every gate as a named task | One file (`.mise.toml`) replaces pyenv + Makefile + per-tool installers, and works the same on macOS, Linux and in CI (`jdx/mise-action`) | pyenv + Make (two tools, Make syntax), asdf (no task runner), direnv |
| **uv** | Creates the venv, resolves and locks, installs, runs tools | 10–100× faster than pip; a real cross-platform lockfile; dependency groups; installs Python too | pip + pip-tools (slow, no groups), Poetry (slower, own build backend), PDM |
| **ruff** | Lint and format | One Rust binary replaces flake8, isort, pyupgrade, black and many plugins, and runs in milliseconds | black + flake8 + isort (three configs, slower) |
| **mypy** (strict) | Static type checking | Mature, strict mode catches `None` and `Any` leaks; the pydantic plugin understands settings models | pyright (fine in the editor via Pylance; mypy stays the CI gate for plugin support) |
| **pytest** + pytest-cov | Tests with a coverage floor | De-facto standard; fixtures; `--strict-markers` stops typo'd markers silently skipping tests | unittest (verbose, no fixtures) |
| **pre-commit** | Runs format, lint, lockfile and secret checks on every commit | Catches problems before they reach a PR; the same hooks run in CI via `pre-commit run --all-files` | Husky (Node-centric), manual discipline |
| **gitleaks** | Secret scanning: staged changes on commit (hook) and the full git history in `mise run ci` | Fast, broad rule set, no service to call. The history scan catches anything committed past the hook (`--no-verify`, web edits) | detect-secrets (baseline file to maintain) |
| **pip-audit** + **bandit** | Dependency CVEs and insecure code patterns (`mise run security`) | Uses the PyPA advisory database; bandit flags `eval`, weak crypto, shell injection | Safety (licensed DB) |
| **Podman** | Build and run images, rootless and daemonless | No root daemon; rootless by default; Docker-compatible CLI; the team standard (Docker is not used) | Docker Desktop (root daemon, licensing) |
| **trivy** | Image vulnerability scan and CycloneDX SBOM | One tool for both; scans an exported archive, so no daemon socket is needed with Podman | Grype + Syft (two tools) |
| **Dev container** | A ready-made environment in VS Code, on Podman | New contributors are productive in one click; same image stages as CI | Manual set-up docs only |
| **FastAPI** + **uvicorn** | HTTP API and ASGI server | Type-hint-driven validation, OpenAPI for free, async-ready for model and tool calls | Flask (sync, no validation), Django (heavier) |
| **pydantic-settings** | Typed configuration | Validates env vars at start-up so a bad value fails the deploy, not the first request | `os.environ` lookups (typos fail late) |
| **typer** | Command-line interface | CLI from type hints; testable with `CliRunner` | argparse (more boilerplate), click (typer is built on it) |
| **httpx** + **tenacity** | HTTP client with retries | Sync and async clients with timeouts; explicit, testable retry policies for flaky upstreams such as model APIs. httpx is still what most AI SDKs use, but it has had no release since December 2024; its successor, httpx2, is maintained under the pydantic organisation. Watch it for a future template release | requests (sync only) |
| **httpx2** (dev only) | Backend for FastAPI's `TestClient` | Starlette 1.10+ deprecates `httpx` as the TestClient backend in favour of httpx2, from the same author | — |

## Tasks

Run `mise tasks` to list them. Every task exits non-zero on failure, so it can gate CI.

| Task | What it does | When to run it |
|---|---|---|
| `mise run bootstrap` | `uv lock` if there is no lockfile, `uv sync`, install git hooks, date any new `.pip-audit-ignore` entries | Once per clone, and after `copier update` |
| `mise run format` | `ruff format .` | Any time (also runs on commit) |
| `mise run lint` | `ruff check .` | While coding |
| `mise run type` | `mypy` in strict mode | While coding |
| `mise run test` | `pytest` with coverage; fails under 80% | While coding |
| `mise run security` | `pip-audit` (dependency CVEs) and `bandit` (code patterns) | Before a release, and when adding dependencies |
| `mise run image` | `podman build --pull=newer --target prod` → `template-sample-app:dev` | Before scanning or smoke-testing |
| `mise run scan` | Validate `.trivyignore`, then trivy on the image; fails on fixable HIGH/CRITICAL | After `image` |
| `mise run sbom` | CycloneDX SBOM of the image → `sbom.cdx.json` (git-ignored) | When you need an inventory |
| `mise run serve` | Run the API locally with auto-reload on `http://127.0.0.1:8000` | Local development |
| `mise run smoke` | Run the built image rootless, read-only (tmpfs `/tmp`), no capabilities, no privilege escalation; check `/health/live`, `/health/ready` and request-ID echo; print the container log if it fails | After `image` |
| `mise run ci` | `uv sync --locked`, all pre-commit hooks, mypy, tests (excluding `live`), pip-audit, bandit, gitleaks over the full history | **Before every push**: CI runs exactly this |

## Daily loop

```bash
git pull && uv sync               # start of day: pick up teammates' dependency changes
mise run lint && mise run test    # while coding (or rely on editor format-on-save)
mise run ci                       # before push: identical to CI
git add -A && git commit -m "feat: ..."   # hooks run: format, lint, lockfile, secrets
git push
```

Use [Conventional Commits](https://www.conventionalcommits.org/) (`feat:`, `fix:`, `chore:`, `docs:`) so `CHANGELOG.md` is easy to maintain.

## Layout

```text
.
├── .copier-answers.yml    your template answers (do not edit by hand; used by copier update)
├── .container/
│   ├── Containerfile      multi-stage: python-base → build → dev / test / prod
│   └── compose.yaml       hardened local run of the prod image
├── .devcontainer/         VS Code dev container on Podman (--userns=keep-id)
├── .github/workflows/
│   ├── ci.yml             calls the template's shared, pinned CI workflow
│   └── release.yml        tag v<version> → amd64/arm64 OCI archives + SBOM + provenance (no registry)
├── .vscode/settings.json  ruff format on save (the dev container sets its own interpreter)
├── .env.example           variable NAMES only (committed); copy to .env.dev/.env.test
├── .gitignore             Python + hardened team rules (secrets, keys, local state)
├── .mise.toml             tool pins + every task
├── .pre-commit-config.yaml
├── .containerignore       keeps .git, .venv, secrets and caches out of the build context
├── .trivyignore           time-boxed vulnerability exceptions (empty by default)
├── pyproject.toml         metadata, dependencies, groups, ruff/mypy/pytest/coverage config
├── uv.lock                exact versions (committed)
├── CHANGELOG.md
├── docs/adr/              this project's architecture decision records
├── src/template_sample_app/
│   ├── __init__.py        __version__ from installed metadata
│   ├── cli.py             typer entry point: `template-sample-app`
│   ├── config.py          typed Settings; fails fast on bad values
│   ├── logging_config.py  JSON logs with request ID
│   └── main.py            create_app() factory, health endpoints, request-ID middleware
├── tests/
└── tools/check_scan_exceptions.py   rejects undocumented or expired .trivyignore entries
```

The **src layout** (`src/template_sample_app/`) means tests import the installed package, not files that happen to sit in the working directory, so packaging mistakes show up in tests rather than in production.

## Quality gates: what each one catches

| Gate | Catches | Threshold and why |
|---|---|---|
| `ruff check` | Bugs (`B`), unused or undefined names (`F`), import order (`I`), outdated syntax (`UP`), naming (`N`), security smells (`S`) | Zero findings. `S101` (assert) is allowed only in `tests/` |
| `ruff format` | Style debates | Formatter output is the style |
| `mypy --strict` | `None` handling, `Any` leaks, wrong call signatures | Strict from day one: retrofitting types later costs far more |
| `pytest --cov` | Behaviour regressions | Coverage floor **80%** with branch coverage: low enough to be achievable, high enough that untested modules stand out |
| `uv-lock` hook | `pyproject.toml` changed without updating `uv.lock` | Lockfile must match |
| `gitleaks` | API keys, tokens and private keys: staged changes (hook) and every commit in history (`mise run ci`) | Any finding blocks the commit or fails CI |
| `pip-audit` | Dependencies with published CVEs | Any finding fails `mise run security` |
| `bandit` | Insecure code patterns in `src/` | Any finding fails |
| `trivy` | OS and Python package CVEs inside the image | Fixable HIGH and CRITICAL fail; unfixed ones are reported but cannot be acted on, so they do not block |

Tests that call real external services are marked `@pytest.mark.live` and are skipped by `mise run ci` (`-m "not live"`). Run them deliberately: `uv run pytest -m live`.

## Configuration and secrets

- `.env.example` is committed and lists variable **names** with safe defaults only. Never put real values in it.
- Copy it to `.env.dev`, `.env.test` or `.env.prod` and fill values locally. Every `.env*` file except the example is git-ignored.
- `APP_ENV` (`dev` by default) picks which file is read at start-up. **Real environment variables always win** over file values, so CI and containers configure the app without files.
- `src/template_sample_app/config.py` declares every setting with a type. A bad value (for example `LOG_LEVEL=LOUD` or `HTTP_PORT=80`) raises at start-up, so a misconfigured deploy fails immediately and visibly.
- Declare any secret setting as `pydantic.SecretStr`. It then prints as `**********` in `template-sample-app config`, in logs and in tracebacks, and you read it with `.get_secret_value()` only where it is used.
- Production values belong in the platform's secret store, or in a Podman secret. They never go in files, images or git.

To hand a secret to a container, declare it into a shell variable without echoing it, then create a Podman secret from that variable:

```bash
read -rs SOME_API_KEY && export SOME_API_KEY        # type or paste the value; it is not shown or kept in history
printf '%s' "$SOME_API_KEY" | podman secret create some_api_key -
unset SOME_API_KEY
podman run --secret some_api_key,type=env,target=SOME_API_KEY template-sample-app:dev
```

Replace `SOME_API_KEY` with the variable name your code reads. To rotate, `podman secret rm some_api_key` and create it again.

## Service runtime baseline

The service starts with the production concerns that are expensive to retrofit:

| Feature | Where | Why |
|---|---|---|
| **App factory** `create_app(settings)` | `main.py` | Tests build an app with test settings; no import-time side effects beyond the default `app` |
| **`GET /health/live`** | `main.py` | Liveness: "the process is up". Keep it trivial so a slow dependency never causes restarts |
| **`GET /health/ready`** | `main.py` | Readiness: "ready for traffic". Extend it to check databases or model endpoints; it returns the service name, version and environment |
| **Request ID** | `main.py` middleware | Each response carries `X-Request-ID`. A caller's ID is reused only if it matches `^[A-Za-z0-9._-]{1,64}$`, which blocks log injection; otherwise a new UUID is generated |
| **JSON logging** | `logging_config.py` | One JSON object per line with `request_id`, ready for any log platform. Set `LOG_JSON=false` for readable local logs |
| **Access log** | `main.py` middleware | Method, path, status and duration are logged with the request ID. uvicorn's own access log is turned off to avoid duplicates |

Try it:

```bash
mise run serve
curl -s http://127.0.0.1:8000/health/ready
curl -si -H 'X-Request-ID: demo-1' http://127.0.0.1:8000/health/live | grep -i x-request-id
uv run template-sample-app config        # validates and prints the effective settings (SecretStr values masked)
```

Interactive API docs are at `http://127.0.0.1:8000/docs` in `dev` and `test`. With `APP_ENV=prod`, `/docs`, `/redoc` and `/openapi.json` are switched off, so production does not advertise its full API surface.

## Containers (Podman)

This project uses **Podman**: rootless and daemonless, with a Docker-compatible CLI. Docker is not required or used. On macOS, Podman runs containers in a small Linux VM (`podman machine`); see the workstation guide.

One multi-stage `.container/Containerfile`:

| Stage | Contents | Used by |
|---|---|---|
| `python-base` | `python:3.15-slim` pinned by digest; OS packages upgraded; **pip removed**; non-root user `app` (uid 10001) | Every stage |
| `build` | uv copied in; locked runtime dependencies and this package installed **non-editable** into `/opt/venv` | Internal |
| `dev` | Plus git and the default groups (dev); venv owned by `app`; source bind-mounted over `/app` | Dev container |
| `test` | Plus `tests/` and `tools/`; runs pytest as `app`, so **the build fails if the tests fail** | CI |
| `prod` | Runtime `/opt/venv` only: no source tree, no uv, no pip, no compiler | `mise run image`, releases |

```bash
podman build -f .container/Containerfile --target test .   # tests inside the image
mise run image                                             # prod image → template-sample-app:dev
mise run scan                                              # fail on fixable HIGH/CRITICAL
mise run smoke                                             # run it hardened, check health endpoints
podman compose -f .container/compose.yaml up               # local run on 127.0.0.1:8000
```

**Why these choices:**

- **Fully qualified image names** (`docker.io/library/python`, `ghcr.io/astral-sh/uv`): Podman does not guess a registry for short names, so builds are unambiguous.
- **Digest pins**: a tag can be re-pointed; a digest cannot. The template release refreshes digests, and `copier update` brings them here. Digests are multi-arch index digests, so the same pin works on Apple silicon (arm64) and on amd64 CI runners.
- **`--pull=newer`** on `mise run image` refreshes the base when a newer patch is published under the same tag (when no digest is pinned).
- **No pip in the image**: uv installs everything. The base image's bundled pip ships its own copies of urllib3, setuptools and others that scanners flag, and pip is not needed at run time.
- **`/opt/venv` outside `/app`**: a bind-mounted source folder never hides or clashes with the environment.
- **`UV_NO_CACHE=1`** and **`.containerignore`**: no uv cache, `.git`, `.venv`, egg-info or secrets end up in layers.
- **Hardened run** (compose and smoke): read-only root filesystem with a `tmpfs` for `/tmp`, all capabilities dropped, `no-new-privileges`, ports bound to `127.0.0.1`. Compose's healthcheck is written in Python because the image deliberately has no curl.
- **Rootless notes**: use host ports of 1024 or higher; add `:Z` to bind mounts on SELinux hosts (Fedora, RHEL). The dev container map your host user to `app` (`keep-id:uid=10001,gid=10001`), so files you create stay yours on the host.
- **Dev container and git hooks**: the git hooks are installed by `mise run bootstrap` **on the host**. The container does not reinstall them: host and container share `.git/hooks`, and each side would point the hook at its own Python. Commit from either side; run `mise run ci` before pushing.

## Vulnerability scanning and exceptions

`mise run scan` fails on **fixable** HIGH and CRITICAL findings (`--ignore-unfixed`). When a finding cannot be fixed yet and the risk is understood, add a time-boxed exception to `.trivyignore`. Each entry needs a reason, an owner and an expiry date:

```text
CVE-2026-12345  # reason: not reachable, we never parse untrusted TAR files; owner: platform-team; expires: 2027-01-31
```

`tools/check_scan_exceptions.py` runs first and fails the scan if any entry lacks these fields, has expired, or expires more than 90 days ahead, so exceptions cannot quietly become permanent. It also refuses a `trivy.yaml`, a VEX file, or `TRIVY_*` settings in `.mise.toml`: trivy reads them automatically, and they could skip paths or suppress findings without any of these checks. Prefer fixing: rebuild with `--pull=newer`, bump the dependency (`uv lock --upgrade-package <name>`), or `copier update` to pick up a newer base digest.

`mise run sbom` writes a CycloneDX SBOM (`sbom.cdx.json`, git-ignored) of the image. CI uploads it as a build artifact.

## Releasing

There is no container registry (template ADR 0011). A release is a GitHub release that carries the image itself:

1. Set `version` in `pyproject.toml` (for example `0.2.0`, or `0.2.0rc1` for a pre-release), run `uv lock`, and merge to `main`.
2. Tag it: `git tag v0.2.0 && git push origin v0.2.0`. The release workflow refuses a tag whose normalised version differs from `pyproject.toml`; `v0.2.0-rc.1` matches `0.2.0rc1` and becomes a pre-release.
3. `.github/workflows/release.yml` runs the gates, builds the image natively on amd64 and arm64, runs the in-image tests, exports each image as an OCI archive, scans it, writes an SBOM, and publishes them with `SHA256SUMS`. It also records build provenance, signed by a separate job that runs none of this project's code. Private repos always skip provenance: GitHub supports it there only on Enterprise Cloud, which the template does not assume.

To use a release:

```bash
gh release download v0.2.0 -R lloydbrian/template-sample-app
sha256sum -c SHA256SUMS
gh attestation verify template-sample-app-0.2.0-linux-arm64.oci.tar -R lloydbrian/template-sample-app   # public repos
podman load -i template-sample-app-0.2.0-linux-arm64.oci.tar
```

**Why no registry:** nothing to authenticate to and no credentials in CI. An archive plus SBOM plus provenance is a complete, verifiable artifact. Adding a registry later is one extra job after the scan.

## Continuous integration

`.github/workflows/ci.yml` is a few lines long. It calls the template's shared workflow at a **pinned version**:

```yaml
uses: lloydbrian/python-project-template/.github/workflows/python-ci.yml@v2.0.0-rc.2
```

The shared workflow installs the pinned mise and runs `mise run ci`. It then builds the `test` stage, builds the image with Podman, scans it with trivy and uploads the SBOM, and runs the smoke test. All third-party actions and pre-commit hooks are pinned by commit SHA.

**Why a shared workflow:** CI logic lives in one place. Fixes and hardening reach every project when `copier update` bumps the pinned version, rather than being copy-pasted into each repo.

Branch protection should require the check named **`check / check`**.

> If the template repo is private, allow access to it from this repo: in the template repo, *Settings → Actions → General → Access*, choose "Accessible from repositories owned by the user".

## Dependencies

| Kind | Where | Command | Shipped in the image? |
|---|---|---|---|
| Runtime libraries | `[project].dependencies` | `uv add <pkg>` | Yes |
| Optional features | `[project.optional-dependencies]` | `uv add --optional <extra> <pkg>`; install with `uv sync --extra <extra>` | Only if installed explicitly |
| Dev tooling (tests, linters) | `[dependency-groups].dev` | `uv add --group dev <pkg>` | No |
| Security tooling | `[dependency-groups].security` | `uv add --group security <pkg>` | No |

- **Dependency groups, not extras, for tooling** (PEP 735): plain `uv sync` installs the `dev` group, and nothing in a group can leak into a published package.
- **Version floors** (`>=`) are the latest releases when this template was released, and never below a version with a published security fix, so nothing can resolve to a known-vulnerable version. `uv.lock` holds the exact versions; `copier update` raises the floors with each template release.
- A service keeps its web framework in `dependencies`, because images install no extras. The `ai` extra holds the data stack (numpy, pandas) for local analysis; anything the running service needs belongs in `dependencies`.
- Upgrade deliberately: `uv lock --upgrade-package <name>` for one package, `uv lock --upgrade` for everything. Then run `mise run ci` and `mise run security`.
- There is no automated dependency bot. Review upgrades on a schedule (for example monthly) and after security advisories.

## Keeping up to date

This repo was generated by [Copier](https://copier.readthedocs.io/). When the template releases a new version:

```bash
uv tool install copier            # once per machine (or: brew install copier)
git switch -c chore/template-update
copier update --skip-answered            # or --vcs-ref vX.Y.Z for a specific release
git status                                # review the diff; resolve any conflicts or *.rej files
mise run bootstrap && mise run ci
```

- Copier replays the template's changes as a three-way merge, so your own edits are kept. Where both sides changed the same lines, it leaves conflict markers for you to resolve.
- Tool versions, base image digests and the shared CI version are computed by the template, so they move forward on every update without new questions.
- Do not hand-edit `.copier-answers.yml`. To change an answer, run `copier update --data <question>=<value>`.
- Read the template's `CHANGELOG.md` before updating across a major version.

## Troubleshooting

| Symptom | Cause and fix |
|---|---|
| `mise ERROR ... is not trusted` | Run `mise trust` in the repo. mise refuses to run config it has not been told to trust |
| `python3.15: command not found` or the wrong Python | Run `mise install`, and make sure `eval "$(mise activate zsh)"` is in `~/.zshrc`; open a new shell |
| `The lockfile at uv.lock needs to be updated` | `pyproject.toml` changed: run `uv lock`, then commit both files |
| pre-commit `uv-lock` hook modified files | Same cause: `git add uv.lock` and commit again |
| Coverage `FAIL Required test coverage of 80% not reached` | Add tests for the uncovered lines shown under `term-missing` |
| `Cannot connect to Podman` / `unable to connect to Podman socket` (macOS) | Start the VM: `podman machine start`. After a macOS upgrade: `podman machine stop && podman machine start` |
| `short-name ... did not resolve to an alias` | Use the fully qualified name (`docker.io/library/...`), as the Containerfile does |
| Build is slow or `exec format error` on Apple silicon | Build for your own architecture (the default). Only use `--platform linux/amd64` when you need it; it runs under emulation |
| `bind: permission denied` on a low port | Rootless Podman cannot bind ports below 1024: use 8000 or higher |
| Permission denied on bind-mounted files (Linux) | Add `:Z` to the mount (SELinux) and use `--userns=keep-id` |
| `trivy` fails with expired or undocumented exceptions | Fix the finding or renew the `.trivyignore` entry with a new reason, owner and expiry |
| VS Code dev container tries to use Docker | In your **user** settings set `"dev.containers.dockerPath": "podman"` |
| `scan`: "trivy config files are not allowed" | Remove `trivy.yaml` or VEX files; record exceptions in `.trivyignore` instead |
| `Validation error for question ...` during `copier update` | An answer is no longer valid under the template's rules (for example quotes in the name). Fix it with `copier update --data <question>=<value>` |
| CI cannot find the shared workflow | The template repo is private or the ref does not exist; see the note under [CI](#continuous-integration) |
